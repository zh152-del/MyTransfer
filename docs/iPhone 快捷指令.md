# iPhone「接收电脑文件」快捷指令 — 搭建说明

目标：电脑上点「选择并发送文件」，iPhone 上**点一下**快捷指令就收完，全程不打开 Safari、
不打开网页、不需要输入 IP、不需要看进度条（进度条在电脑上）。

## 先回答：有没有「添加链接」直接加进来？

**没有，Apple 不提供。** 快捷指令不支持远程创建，`.shortcut` 只能在你自己手机上搭完才导出。
所以只能手动加动作——下面三套方案都是纯系统自带动作，几分钟能搭完。

> 想自己导出分享：搭好后 → 右上角 `i` →「共享快捷指令」，会生成 iCloud 链接，
> 别人点开就能「添加不受信任的快捷指令」。前提是手机上已经搭好了。

## 先分清这几个「获取」（你翻车就翻在这儿）

截图里那三个带橙色 `x` 图标的「获取」，都是**「获取变量」**动作，它只能把一个变量里的值取出来，
**不能拆文字**。名字相近的几个动作是两回事：

| 动作 | 图标 | 干什么 |
|------|------|--------|
| **获取 URL 内容** | 🟢 绿 | 去下载一个网址的内容（这是你要用的主力动作） |
| **获取变量** | 🟠 橙 x | 把某个变量的值取出来（你截图里那三个都是它） |
| **获取词典值 / 字典值** | 🟠 橙 | 从一个字典里按 key 取值（JSON 版才用） |
| **拆分文本** | 🟠 橙 | 把一段文字按换行/逗号**切成一摞** |
| **从列表获取第 N 项** | 🟠 橙 | 从切好的那一摞里捡第 N 段 |

**本方案一个都不用**，只需要「获取 URL 内容」「保存文件」「显示通知」这三个最常见的动作。

## 三套方案怎么选

| | 方案 C（`/url?w=`，**推荐**） | 方案 B（`/hello.txt` 四行） | 方案 A（JSON） |
|---|---|---|---|
| 动作数 | **6 个** | 8 个 | 11 个 |
| 用到难找的动作吗 | 不，全是常用动作 | 要「拆分文本」+「取列表第 N 项」 | 要「从文本获取词典」 |
| 前提 | 电脑端已升级（支持 `/url`） | 同左 | 动作库搜得到 JSON 动作 |

> 搜不到「从文本获取 JSON」是 iOS 的老问题：那个动作真名 **「从文本获取词典」**，
> 在「脚本」动作组下，要点顶部「脚本」标签或搜「词典」/「Dictionary」才出得来，搜「JSON」常不列。

## 一、这套方案为什么不需要输入 IP

电脑启动后用 Bonjour（mDNS）在局域网广播：

```
服务类型：_http._tcp.local
服务名：  MyTransfer._http._tcp.local
TXT:      port=8765
```

iPhone 的 iOS 自带 mDNS 解析器认识 `.local` 结尾的名字（和 AirPlay 打印、Mac 文件共享同一个机制），
它会问「MyTransfer.local 是谁」，电脑答「在这儿，端口 8765」。

所以网址直接写 `http://MyTransfer.local:8765/...` 就行。电脑换 IP 也不影响——名字不变，
名字后面挂的 IP 变了没关系，每次实时解析。

> 这条链路依赖 Windows 端的 mDNS 广播（已用探针验证，见《测试结果》）。
> 万一 iPhone 解析不了 `.local`，看第七节的备选方案，只改一个网址。

## 三、方案 C：6 个动作完成（★推荐）

打开「快捷指令」App → 右上角 `+` → 名字写 **接收电脑文件**。

电脑端先选好要发的文件，然后照着加这 6 个动作：

| # | 动作 | 参数怎么填 |
|---|------|-----------|
| 1 | **获取 URL 内容** | 操作=获取；**网址** = `http://MyTransfer.local:8765/url?w=name`；方法 GET；内容类型 = **文本** |
| 2 | **获取 URL 内容** | 网址 = `http://MyTransfer.local:8765/url?w=file`；内容类型 = **文本** |
| 3 | **获取 URL 内容** | 网址 = 选「**使用上一个动作的输出**」（就是第 2 步拿到的下载地址）；内容类型 = **文件** |
| 4 | **保存文件** | 这句读作「将 **[要存的东西]** 存储到 **[文件夹]**」：左边那格 = 第 3 步（下载下来的文件），右边那格 = 文件 App → 我的 iPhone → **MyTransfer**；「询问保存的位置」**关掉**；「如果存在则替换」**打开**。**文件名那格不用填**，存的时候自动用下载时的名字（就是第 1 步那个）；只有你想改名才去动作里展开「文件名」一行拖第 1 步 |
| 5 | **获取 URL 内容** | 网址 = `http://MyTransfer.local:8765/url?w=done`；内容类型 = 文本 —— **这一步不能省**，问完这一句就等于告诉电脑「我收完了、多少字节」，6 步闭环 |
| 6 | **显示通知** | 标题 = 接收完成；正文 = 拖一个「文本」进去：第 1 步 + `（已保存到 MyTransfer）`；显示 = 横幅 |

最后右上角 `✓`。

> **2026-10-05 改过一版：第 5 步现在会自动回报，不用再多一个动作。**
> 旧设计是「`w=done` 只把回报地址吐回来，手机上还得再拿这个地址去获取一次」，
> 那一步在真机上非常容易接错（把「上一个动作的输出」插错位置就整条指令跑飞）。
> 现在 `w=done` **问一次就把事办了**，直接回 `接收完成，已回报 N 字节`。

### 第 5 步千万别挂错东西（真机截图里踩过）

`获取 URL 内容` 这个动作的「网址」那一格，**必须手打 / 从菜单里挑完整的网址文本**，
不能把「保存文件」那个动作的输出（一个**文件对象**，蓝色方块带下载图标的）
拖到网址格子里 —— 那样等于「获取一个本地文件内容」，会直接报错。

正确对照（按你这张截图改完之后的样子）：

| 动作 | 网址格 / 文件名格 | 那格应该长什么样 |
|------|------------------|-----------------|
| 1 | 网址 | 蓝色**网址文本** `…/url?w=name` |
| 2 | 网址 | 蓝色**网址文本** `…/url?w=file` |
| 3 | 网址 | 「使用上一个动作的输出」，一个**绿色文字块** |
| 4 | 左边那格「要存的东西」 | 拖**第 3 步**（下载的文件）—— 这就是对的，不用改 |
| 5 | 网址 | 蓝色**网址文本** `…/url?w=done` |
| 6 | 正文 | 拖一个「文本」进去：第 1 步 + `（已保存到 MyTransfer）` |

### 为什么要 `?w=name` 这么几段

`/url` 只会回**一行**你要的东西，所以每个字段各问一次：

| 网址 | 电脑回你什么（本机实测） |
|---|---|
| `/url?w=name` | `测试100MB.bin` |
| `/url?w=file` | `http://192.168.0.199:8765/file/e86cdb5d` |
| `/url?w=done` | 字节发完后：`接收完成，已回报 314572800 字节`（**同时已经完成校验**）；文件还没发完时会回`回报地址`，让你自己再去访问一次 |
| `/url?w=fail` | 字节发完后：回 `已报告失败`，**同时**服务端把任务判成 `error`；任务已结束时返回空 |

第 5 步不用你在手机上拼字节数、不用算，电脑自己知道发了几百 MB。

> 第 5 步没做，电脑只能停在那句「已发完，等待 iPhone 回报字节数」，
> 永远不显示「验证成功」。

三个已经踩过/确认过的坑：

- **第 5 步是下载完之后才问的**，那一刻电脑端正好卡在「已发完、等你回报」的状态，
  早先版本在这里返回过空字符串，已经修掉了（`verifying` 状态也算「任务还活着」）。
- **不用加 `?w=fail`**。它只在你想主动告诉电脑「我这边失败了」时才用（比如保存报错，
  想让电脑立刻判 `error` 而不是干等），日常收文件加它反而多一个动作。
- **电脑上还没选文件时**，`w=name` / `w=file` 会返回空值（零长度），手机上会直接报错停下，
  不会拿个空地址去下文件。这种情况就是电脑端还没点「选择并发送文件」。

**改完代码要重启电脑端**（双击桌面那个 bat），新逻辑才生效；
手机上的快捷指令不用改结构，只要把第 4、5、6 步的插块按上面那张表对一遍就行。

## 三补：卡住了？看电脑日志，一眼定位断在第几步

**2026-10-05 加的。** 之前你跑出「日志里只有 `w=name`，从第二步开始一条都没有」，
但根本看不出手机到底发出去没有、发出的是什么——现在每一步都留痕了。

每次启动电脑端，日志会原样落一份到：

```
MyTransfer\logs\server_20261005-195700.log
```

也可以直接看程序界面里的日志窗口（同一个内容），或者每次运行完我这边就会告诉你文件在哪。

### 日志长这样

```
19:54:56  收到请求 /url?w=name  ← 192.168.0.200（Python-urllib/3.13）  [第 1 步 取文件名]
19:54:56      应答 200，11 字节：'测试300MB.bin'
19:54:56  收到请求 /url?w=file  ← 192.168.0.200（Python-urllib/3.13）  [第 2 步 取下载地址]
19:54:56      应答 200，39 字节：'http://192.168.0.199:8765/file/be32796c'
19:54:57  收到请求 /file/be32796c  ← 192.168.0.200（...）  [第 3 步 下载文件 be32796c]
19:54:57  开始发送 测试300MB.bin
19:54:58  字节流发送完毕（300.0 MB），等待 iPhone 回报字节数
19:54:58  收到请求 /url?w=done  ← 192.168.0.200（...）  [第 4 步 回报接收完成]
19:54:58  [OK] 字节数 314572800/314572800 一致；发送流 SHA256 与源文件一致
19:54:58  [OK] 耗时 1.28 秒，平均 233.9 MB/s
19:54:58      应答 200，21 字节：'接收完成，已回报 314572800 字节'
```

一条请求 = 两行：**「收到请求（第几步 ← 哪台设备）」** + **「应答（回了什么）」**。
`←` 后面是手机 IP；方括号里是这一步在整套流程里叫什么。

### 对照表：日志里出现什么 = 哪里出问题

| 日志里看到的 | 说明 |
|---|---|
| 只有 `[第 1 步 取文件名]`，后面什么都没有 | **第 2 步根本没发出请求**。手机上第 2 步网址没填、或填成了默认网址（还指着 apple.com）、或整个动作没保存上 |
| `请求了不认识的地址 /xxx（多半是快捷指令里网址手打错了）` | 请求**到了**服务器，但网址不对。照抄一遍第 3 节那三个网址 |
| `问了不认识的字段 w=xxx` | `?w=` 后面填错了，应该是 `name` / `file` / `done` |
| `应答 200，0 字节：''` | 服务器回了空——通常是「电脑还没选文件」，先去电脑上点「选择并发送文件」 |
| `应答 200，34 字节：'网址里应该带 ?w=name / ?w=file / ?w=done'` | 手机上网址漏了 `?w=` 这一段 |
| `[第 2 步 取下载地址]` 有、但 `[第 3 步 下载文件]` 没有 | 手机拿到了地址却没去下：第 3 步的「内容类型」必须选 **文件**，选成文本就只会下成一段乱码 |
| `iPhone 中途断开连接（已发 41.3%）` | 传一半断了（锁屏 / 切出去 / 网络抖）。手机上删 `.part` 残片，电脑上重发一次 |
| 全都对、但电脑一直 `等待 iPhone 回报字节数` | 第 5 步没做，或第 5 步网址不是 `?w=done` |

> 服务端对 `?w=` 里的 `W=` 大写、前后空格都做了容错，手抖也不会失败。

## 四、方案 B：`/hello.txt` 四行版（8 个动作）

如果你更想一次拿全，用 `http://MyTransfer.local:8765/hello.txt`，它返回 4 行：

```
测试100MB.bin
104857600
http://192.168.0.199:8765/file/0421f2e6
http://192.168.0.199:8765/done?bytes=104857600&id=0421f2e6
```

然后用 **「拆分文本」**（Separate Text，按换行符切）→ 得到列表 →
**「从列表获取第 N 项」** 拿第 1 / 3 / 4 行，剩下的和方案 C 一样。

> 「从列表获取第 N 项」就是那个橙色 `x` 的「获取」动作，只是它输入的是列表、输出选「列表项」。

| 4 | 从 JSON 获取变量 | 字典=第 3 步输出；变量=`name` |
| 5 | 从 JSON 获取变量 | 字典=第 3 步输出；变量=`size`（参考） |

## 六、以后怎么用

```
电脑：双击「启动 MyTransfer.bat」→ 点「选择并发送文件」→ 选 video.mp4
      → 界面显示「等待 iPhone 打开快捷指令」，进度条 0%

iPhone：连着和电脑同一个 Wi-Fi（不能是 5G/蜂窝）
      → 点一下「接收电脑文件」
      → 快捷指令最后一屏会停在下载，等它自己结束
      → 弹出「接收完成」通知

电脑：进度条跑完 → 显示「验证成功：字节数一致 + 发送流 SHA256 一致」
```

文件落在 **「文件」App → 我的 iPhone → MyTransfer → video.mp4**。

收到一半失败：iPhone 上留 `video.mp4.part` 残片，电脑显示「iPhone 中途断开连接（已发 40.8%）」。
**删掉残片再点一次**，电脑重发整个文件（不是续传，最不容易出错）。

## 七、iOS 的真实限制（绕不过去的）

| 限制 | 实际情况 | 应对 |
|------|---------|------|
| **快捷指令不能建文件夹** | 系统不提供 | 手动建一次 MyTransfer |
| **不能算文件 SHA256** | 没有任何 Hash 文件动作 | iPhone 只回报字节数，SHA256 由电脑对实际发出的字节流算 |
| **不能浏览 Bonjour 服务列表** | 没有这类动作 | 网址写 `MyTransfer.local`，让 iOS 自己解析 |
| **大文件有被系统掐掉的风险** | iOS 按内存压力杀后台进程 | 先 100MB 试，稳了再 300/500MB，传的时候别锁屏 |
| **锁屏会被挂起** | 快捷指令不是常驻后台 | 传输期间保持亮屏（这条必须实机验） |
| **不能长期常驻** | 进程一关就没了 | 点一下才开始 |
| **低电量模式** | 会拖慢/跳过自动化 | 传大文件前关掉 |
| **必须同一个 Wi-Fi** | mDNS 是链路本地的 | 连主 Wi-Fi，**别连访客网络**（大多隔离多播） |

### 备选：万一 iPhone 解析不了 `.local`

1. 电脑上点「复制地址」，得到 `http://192.168.0.199:8765/hello.txt`
2. 方案 C 只改**第 1、2、5 步**三个网址的域名部分（`/url?w=name` 那段保留），
   换成 `http://192.168.0.199:8765/url?w=name` 这样；
   第 3 步用的是「上一个动作的输出」，不用改。

一次性配置，之后还是点一下就收。

## 八、几个可能踩到的坑

- **手机在 5G / 蜂窝网**：`.local` 一定解析不了，永远连不上。 Wi-Fi 要和电脑同一个网络。
- **「如果存在则替换」没开**：同名文件第二次收会失败。一定开。
- **点了没反应**：看电脑界面右上角绿灯是不是灰的；看手机是不是同一个 Wi-Fi。
- **保存位置不对**：第 4 步「存储到」选文件夹 MyTransfer，「询问保存的位置」必须关。
- **收到 0 字节**：电脑上刚选完文件没等 iPhone 就连点，重发一次即可。
- **搜动作搜不到**：方案 C 只用「URL」「保存文件」「通知」三个词去搜，都能出来。
