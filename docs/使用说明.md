# MyTransfer 使用说明（电脑 → iPhone 局域网传文件）

一句总结：**电脑上选文件，iPhone 上点一下快捷指令，完事。** 电脑负责所有复杂的事
（发现、发送、进度、速度、校验、日志），iPhone 只负责接住文件并保存。

---

## 一、运行

### 方式 A：双击（推荐）

两种方式，随便选一个：

- **桌面上的 `MyTransfer.bat`**（最省事，桌面上就有那个图标）
- 项目目录里的 **`启动 MyTransfer.bat`**

会弹出程序界面窗口（优先用 `pythonw` 启动，**不弹黑窗**，跟普通软件一样；
万一没装对 Python 会自动退回控制台模式，直接看得见报错）。
关掉程序界面就是退出。

### 方式 B：命令行

```bat
python MyTransfer.py
python MyTransfer.py --port 9000          # 换端口（8765 被占用时用）
python MyTransfer.py --no-ui              # 只跑服务端，不弹界面（测试用）
python MyTransfer.py --send D:\a.mp4      # 启动时直接指定要发的文件
```

需要 Python 3.10 以上。界面部分只用标准库 tkinter + 标准库 HTTP 服务，
**不装任何第三方包也能跑**（只有点「二维码」按钮才需要 `qrcode`）。

防火墙：程序启动时会自动尝试添加两条放行规则（传输端口 + mDNS 的 5353）。
提示权限不足时，用管理员身份再执行一次即可，规则不会重复。

## 二、第一次配置

1. 电脑上双击启动脚本，界面右上角显示 **「服务运行中」**，地址一行是
   `http://MyTransfer.local:8765`。
2. 按《[iPhone 快捷指令.md](iPhone%20快捷指令.md)》搭好 iPhone 侧的「接收电脑文件」快捷指令
   （里面还有「iPhone 解析不了 .local 怎么办」的备选方案）。
3. 之后每次传文件都不用再配。

## 三、日常用法

```
1. 电脑上点「选择并发送文件」，选一个文件
2. 界面显示「准备就绪，等待 iPhone 取文件」，进度条 0%
3. iPhone 上点一下「接收电脑文件」
4. 电脑进度条开始跑：百分比、已发/总数、速度、剩余时间、当前状态
5. 发完电脑上显示：
      ✓ 验证成功：字节数一致 + 发送流 SHA256 一致
      耗时 2.04 秒，平均 245.3 MB/s
6. 手机去「文件」App → 我的 iPhone → MyTransfer 里看文件
```

界面上的四行状态分别对应：

| 位置 | 显示什么 |
|------|---------|
| 右上 | 服务是否在跑；灯泡 = iPhone 有没有连上 |
| `iPhone：` 一行 | 未连接 / 已连接（正在接收）/ 已完成 |
| 地址那一行 | iPhone 应该用的网址 `http://MyTransfer.local:8765` |
| 当前任务 | 文件名、进度条、百分比、已传/总量、速度、剩余时间、状态 |
| 验证那一行 | ✓ 验证成功 / ✕ 验证失败 / 校验中… |
| 日志 | 每次操作的完整时间线，也存到 `logs/server_*.log` |

## 四、文件是怎么传的

- 走局域网 **HTTP 流式分块**，每块 4MB，读完一块发一块，发完释放，
  **不会把整个文件读进内存**。
- iPhone 只需 4 次请求，不用打开任何网页：
  1. `GET /url?w=name` — 拿文件名（快捷指令保存文件时用）
  2. `GET /url?w=file` — 拿下载地址
  3. `GET <上一步的下载地址>` — 拉文件
  4. `GET /url?w=done` — **问这一次就等于回报「我收到了多少字节」**，电脑上当场出「验证成功」
- `GET /url?w=fail` 是「我这边失败了」的入口，iPhone 保存不成功时走它，
  电脑上立刻判 `error`（不会干等着）。日常收文件不用它。
- 老的显式接口 `GET /done?bytes=...&id=...` 仍然保留，`/url?w=done` 内部就是调它，
  以后别的客户端（比如模拟器）也能直接用。
- `w` 乱填（漏写、拼错、打成大写）会返回提示串 `网址里应该带 ?w=name / ?w=file / ?w=done`，
  电脑端不会静默。`W=` 大写、前后带空格都做了容错，不会误伤手抖。
- **每个请求在日志里留两条痕**：`收到请求 … [第 N 步 名称] ← 手机IP` 和 `应答 … 回了什么`。
  快捷指令断在第几步，看 `logs/server_*.log` 一眼就知道（详见《iPhone 快捷指令.md》「三补」）。
- **电脑端改过代码之后必须重启一次**（双击桌面那个 bat 就行），新接口才会生效。
- 老的 `GET /hello`（JSON）和 `GET /hello.txt`（4 行纯文本）也还在，是给别的写法留的后路：
  1. `GET /hello` — 拿任务信息（服务名、地址、端口、任务）
  2. `GET /file/<id>` — 拉文件
  3. `GET /done?bytes=...` — 回报「我收到了多少字节」
- `/hello.txt` 是纯文本版，返回 4 行：
  文件名 / 字节数 / 下载地址 / 回报地址。这样 iPhone 侧用「按换行取第几段」就能拆，
  **不需要 iOS 的 JSON 动作**（那个动作在动作库里搜「JSON」经常搜不出来）。
  详见《iPhone 快捷指令.md》第三节。
- 完整性校验（电脑端做的，不指望 iPhone）：
  - 发送前对**源文件**流式算 SHA256（8MB 分块）
  - 发送时对**实际发出去的字节流**同步算 SHA256
  - iPhone 回报的字节数
  - 三项都对上才显示「验证成功」；字节数对不上就明说「验证失败」，不蒙混
- iPhone 侧若是中途断线，电脑上写「iPhone 中途断开连接（已发 40.8%）」，
  并保留已发进度；重新点一次快捷指令，电脑自动重发整个文件。

## 五、目录里都有什么

| 文件 | 作用 |
|------|------|
| `MyTransfer.py` | 启动入口（服务 + 界面） |
| `mt_server.py` | HTTP 服务、传输引擎、mDNS 广播、任务状态机、日志 |
| `mt_ui.py` | 桌面界面 |
| `启动 MyTransfer.bat` | 一键启动（GBK 编码，双击即用） |
| `requirements.txt` | 依赖（只有可选的 qrcode） |
| `tools/sim_iphone.py` | 模拟 iPhone 的接收端，用来自动化测试和联调 |
| `tools/url_flow.py` | 按快捷指令真实动作顺序验 `GET /url?w=`（6 步对照，推荐先跑这个） |
| `tools/run_test.py` | 测试驱动：起服务、真传、采样内存、校验、跑异常场景 |
| `tools/mem_ui.py` | 带界面跑一次传文件，量进程内存峰值（验证不随文件大小涨） |
| `tools/probe_mdns.py` | mDNS 探针：验证电脑是不是真的在广播 Bonjour |
| `tools/capture_ui.py` | 开发自检用：把界面推进「传输中」再截图 |
| `tools/regen_desktop_bat.py` | 桌面启动器生成器：把模板转成 `桌面\MyTransfer.bat`（自动处理 GBK + CRLF） |
| `tools/MyTransfer.bat.tpl` | 桌面启动器模板（改完跑上面那个脚本重新生成） |
| `docs/iPhone 快捷指令.md` | iPhone 侧搭建说明书 |
| `docs/测试结果.md` | 实测数据（100/300/500MB、内存、异常场景） |
| `logs/server_<时间戳>.log` | 每次启动电脑端原样落一份完整日志（UI 窗口里是同一份） |
| `recv/` | 测试收到的文件 |

## 六、出问题先看这里

| 现象 | 原因 / 处理 |
|------|-----------|
| 界面右上角「服务未启动」 | 端口 8765 被别的程序占了，用 `--port 9000` 重启 |
| iPhone 连不上、提示解析失败 | 不在同一个 Wi-Fi；或路由器隔离了多播。服务每 20 秒重播一次，先等一会儿再点；实在不行点「复制地址」用 IP 兜底（一次） |
| 界面一直「等待 iPhone 打开快捷指令」 | iPhone 上的快捷指令还没点，或网址写错了 |
| 收到 0 字节 / 快捷指令报错 | 文件名含特殊字符的话换个简单名字；再点一次重试 |
| 显示「验证失败：iPhone 回报 N 字节」 | iPhone 那边没存全，去「文件」App 删掉残片重来 |
| 「传输流损坏」 | 极罕见，说明发出去的字节变了；先重发，还出现就查硬盘/内存 |
| 日志里只有 `[第 1 步 取文件名]`，第 2 步往后一条都没有 | 手机上第 2 步**压根没发出请求**——多半是那个动作里的网址还是默认的（指向 apple.com）。去《iPhone 快捷指令.md》「三补」那张对照表照着改 |
| 传大文件 iPhone 上转了一半没了 | iOS 内存压力杀了快捷指令（第五节那条限制），保持亮屏、关低电量模式、从 100MB 起步试 |

## 七、自己跑一遍测试

```bat
python tools/run_test.py 100
python tools/run_test.py 300
python tools/run_test.py 500
python tools/run_test.py 500 --break 40      # 传到 40% 时模拟 iPhone 断线
python tools/run_test.py 500 --lie           # 模拟 iPhone 谎报字节数
python tools/run_test.py 500 --fail          # 模拟快捷指令报告失败
python tools/probe_mdns.py                   # 验证 Bonjour 广播
```

每个用例都会打印：耗时、速度、服务端内存峰值、接收字节数、接收端 SHA256 是否一致、
服务端最终状态、服务端自己打的日志。
